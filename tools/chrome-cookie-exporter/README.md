# Chrome Cookie Exporter

本工具是一个本地 Chrome 扩展，用来把当前浏览器里的闲鱼相关 Cookie 导出成项目现有飞书 Bot 可直接接受的纯文本格式。

## 用途

适用流程：

1. 你已经在 Chrome 里登录闲鱼网页版
2. 进入闲鱼聊天页或相关页面
3. 点击扩展图标
4. 扩展自动复制 Cookie 文本
5. 把文本粘贴给飞书 Bot

这个扩展不会自动上传 Cookie，也不会改动仓库里的 Python 服务端流程。

## 加载方式

1. 打开 Chrome
2. 访问 `chrome://extensions`
3. 打开右上角“开发者模式”
4. 点击“加载已解压的扩展程序”
5. 选择本目录：`tools/chrome-cookie-exporter/`

## 默认行为

- 默认导出的是`运行时恢复包`，不是旧版的“关键 Cookie 摘要”
- 默认要求当前活动标签页是闲鱼/Goofish/Taobao 相关页面
- 打开扩展弹窗后会立即尝试复制到剪贴板
- 弹窗默认只保留紧凑状态、就绪摘要、可复制文本、一个主按钮和一个次级诊断入口
- 自动复制失败时，弹窗仍会保留导出的文本供手动复制

### 1. 运行时恢复包是默认路径

默认模式会围绕真实运行时请求面收集 Cookie：

1. `https://h5api.m.goofish.com/`
2. `https://www.goofish.com/`
3. `https://passport.goofish.com/`
4. `https://www.taobao.com/`

扩展会按这个顺序调用 `chrome.cookies.getAll({ url })`，并保留每个 Cookie 名的第一次出现结果。这样导出的结果更接近 Chrome 真正会发给闲鱼运行时接口的 Cookie 头，而不是只保留少量摘要键。

因此，默认导出文本通常会明显长于旧版本。这是预期行为，不代表导出错了，反而更符合项目当前恢复链路：

- `main.py` 会把整段 Cookie 文本原样保存并继续透传给 websocket 握手
- 运行时强依赖读取的是 `unb`、`_m_h5_tk`、`cookie2`、`cna`
- `XSRF-TOKEN` 在部分请求里仍然有帮助，但不再被视为“缺了就一定无法恢复”的硬失败项
- 真实可恢复的 Cookie 串通常还会包含 `x5sec`、`tfstk`、`_m_h5_tk_enc` 等补充项

### 2. 诊断摘要只是次级排查模式

弹窗里的`诊断摘要`只用于快速检查关键摘要键是否缺失，不是推荐的主提交流程。

诊断摘要保留的稳定顺序是：

- `unb`
- `_m_h5_tk`
- `cookie2`
- `cna`
- `XSRF-TOKEN`
- `x5sec`

只有当你想快速比对“哪些核心键已经出现、哪些还没出现”时，才建议切到诊断摘要。真正提交给飞书 Bot 做恢复时，优先使用默认的`运行时恢复包`。

### 3. 导出格式必须保持 Cookie Header 纯文本

扩展导出的文本仍然必须是项目现有运行时可以直接消费的单行 Cookie header：

- 格式：`key=value; key=value; key=value`
- 分隔符必须是 `"; "`（分号 + 单个空格）
- 没有 JSON 包装
- 没有换行
- 没有尾部分号

### 4. 弹窗信号怎么理解

弹窗现在会分开表达三件事：

- `飞书入口识别`
  - 只表示当前文本是否满足飞书入口识别的最小形状
  - 最低门槛仍然只是 `unb`、`_m_h5_tk`、`cookie2`、`cna` 里命中至少 2 个
- `运行时关键项`
  - 关注 `unb`、`_m_h5_tk`、`cookie2`、`cna` 是否齐全
- `推荐补充项`
  - 关注 `XSRF-TOKEN`、`x5sec`、`tfstk`、`_m_h5_tk_enc` 是否齐全

注意：`飞书入口识别：已满足` 不等于 `运行时一定能恢复`。如果运行时关键项或推荐补充项仍然缺失，弹窗会继续提示。

其中 `可选补充项缺失：...` 只是信息提示，不等于失败。它表示这份 Cookie 包还可以更完整，但不自动代表当前恢复一定会失败。

### 5. 刷新或滑块后要重新导出

如果你刚完成了页面刷新、重新登录、过滑块、人机验证或其他会刷新 Cookie 的动作，请立刻重新打开扩展再导出一次。不要继续提交之前那一份旧文本。

如果浏览器当前不允许自动写入剪贴板，弹窗仍会展示导出的文本，并提示你手动复制。

## 弹窗按钮

- `复制`：主操作，重新把当前文本写入剪贴板
- `诊断` / `返回默认导出`：在默认恢复路径和次级排查路径之间切换
- `忽略页面校验后重试`：只会在页面校验失败时出现，允许你手动放宽一次当前页限制

## 手工验证与当前会话缺口

本次会话已经完成了 Node 级别的 helper/popup 自动化验证，但还没有在真实登录态 Chrome 里完成下面这组人工对照，所以当前仍然无法在此会话内证明：

- 扩展导出的运行时恢复包与真实 `https://h5api.m.goofish.com/` 请求头完全同键集合
- 过滑块或刷新后重新打开扩展再导出的路径在真实浏览器里已经手工验证完毕

建议至少做一次下面的烟测：

1. 登录 Goofish 网页版
2. 打开 Chrome DevTools，抓一条真实的 `https://h5api.m.goofish.com/` 请求
3. 复制那条请求的 `request-cookie` 头
4. 立即点击扩展，导出默认的`运行时恢复包`
5. 把两边都归一化成 Cookie key 集合后比较
6. 记录：
   - 真实请求头 key 数
   - 扩展导出 key 数
   - 扩展缺少哪些 key
   - 扩展多出哪些 key
   - 导出文本是否仍然满足 `key=value; key=value` 的运行时解析格式
7. 把导出文本提交给飞书 Bot 观察恢复情况
8. 如果页面要求刷新、重新登录或过滑块，完成后立即再导出一次，并重复上面的对照

## 隐私说明

- 扩展只在本地运行
- 不会把 Cookie 发到任何外部服务
- 不会把导出的 Cookie 持久化到扩展存储

Cookie 文本本身就是敏感凭据，只应该粘贴给你自己控制的飞书 Bot。
